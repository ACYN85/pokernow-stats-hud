# Pot Odds Phase 1

> Historical phase record. The current V1 UI contract supersedes the placement and hide policies below: `boardCompanionLayout.js` owns one complete five-slot board envelope, pot odds always use its LEFT slot, and the host is table-scoped with `CALL` / `ZERO` / `UNKNOWN` content. Fold, all-in, terminal, and between-hands states render ZERO instead of hiding. Hero cards and a collision-selected RIGHT fallback are no longer production anchors. See `BOARD_COMPANION_LAYOUT.md`.

Build `candidate-pot-odds-community-board-anchor-20260820-1832` preserves the ephemeral canonical-self live call-decision indicator, heads-up all-in fix, ordinary-preflop commitment floor, authoritative live-state continuity, Phase 1.9 stable signal-driven overlay, and compact vertical Call/Need UI. This patch changes only placement: the community board is now the preferred visual anchor.

## Source and semantics

- `PokerSemanticHandLedger.liveBettingState()` is a read-only view of the existing bounded merged-state observations. It reuses certified `tB` absolute street commitments, incremental semantic actions, `pITT/cPI` actor identity, `pGS` fold/all-in state, and current stacks.
- `potOdds.js` computes only the additional call amount, eligible pot before the call, pot after call, and raw pre-rake break-even equity.
- Complete per-player total contributions are capped at the local user's contestable contribution level. This retains folded-player dead money and excludes unreachable all-in excess.
- Ordinary non-all-in preflop decisions use the complete sum of live street commitments as a floor under the authoritative named pot. This counts blinds, straddles represented as commitments, limps/calls, raises, hero's posted chips, and folded dead money without adding commitments to an already larger named pot.
- Explicit resolved side-pot inputs are supported. Incomplete recovered histories, unresolved side pots, missing stacks/action state, and ambiguous all-in eligibility fail closed.
- The setting `showPotOdds` is default-on in version 8 of the existing `hudUiPreferences` record.

## UI and diagnostics

Only a supported decision owned by canonical `registered.currentPlayer.id` can render the compact indicator. It remains one 100×60 panel with a Pot Odds heading and separate Call/Need rows. Its native detail tooltip shows eligible pot, call, pot after call, break-even equity, and the before-rake/future-betting limitation. `PokerNowHUDPotOdds.currentDecision()` returns a defensive copy of the current supported, idle, or unsupported decision.

The panel uses the same extension-owned body root and direct fixed `style.left`/`style.top` viewport coordinates with no transform. Each legitimate pass queries visible card containers outside player seats, selects a horizontally aligned three-to-five-card community row, and unions its rectangles. The panel centers vertically ten pixels left of that union. If left is bounded or intersects a measured pot display, action control, or self HUD, ten pixels right is the only board-side fallback. The panel never overlaps the board itself.

If a postflop decision arrives before usable board DOM, the supported decision is retained through the existing six-frame bounded acquisition. Only after that bounded proof of missing board geometry can the preserved hero-hole-card resolver act as fallback; any later board mutation immediately restores board-first placement. `placementInfo()` exposes `chosenAnchorType`, `boardRectUsed`, `selectedSide`, `proposedPanelRect`, collision candidates/obstacles, suppression reason, and `fallbackUsed`.

Ordinary runtime completion requires a successful bounded placement plus a connected, non-hidden, nonzero pill intersecting the viewport. It deliberately performs no recurring computed-style, paint-stack, clipping-ancestry, or transform-string integrity scan. `PokerNowHUDPotOdds.placementInfo()` exposes the latest placement, mounted/viewport result, render revision, and aggregate retry/DOM-write counters. The production fixture separately checks computed style and DOM geometry.

Missing anchor geometry is retained through at most six animation-frame stabilization attempts. After that bounded burst the overlay stops all polling and waits for a legitimate decision, setting, viewport, board/card `ResizeObserver`, or real table mutation signal. Successful placement stops immediately, and an idle/unsupported decision cancels pending work. No timer retry or autonomous integrity watchdog is added.

Live pot-odds observations have independent bounded continuity backed by `PokerSemanticHandLedger`, so they are not gated on finalized-hand ownership. Authoritative merged PokerNow state updates this live projection; purely visual seat/table reconciliation records preservation without mutation. New hands, terminal settlement, stopped/broken/waiting lifecycle, an authoritative local-seat departure, explicit session reset, and table/page cleanup clear it. `currentDecision().evidence.liveStateProvenance` exposes bounded last-update, last-reset, and last-visual-reconcile ownership evidence.

Render-relevant decision changes now use a compact fingerprint and monotonically increasing UI revision. Unsupported/idle to supported, supported price/pot changes, supported to idle, and Show Pot Odds changes schedule one coalesced animation-frame render directly from the semantic decision path. Viewport and seat reconciliation remain harmless repositioning signals rather than prerequisites for initial display. `placementInfo()` includes the current revision/fingerprint, decision-change time, scheduled/executed times, trigger, pending/coalesced state, and last mounted fingerprint.

`PokerNowHUDPotOdds.debugTimeline()` returns a defensive copy of a 96-event bounded forensic buffer plus the current decision, placement, and aggregate visibility counters. It records meaningful authoritative observation, decision commit, render scheduling/execution, host ownership, anchor availability/replacement, placement, bounded retry state, and linked before/after viewport evidence. There is no slow invisible cycle or self-integrity stream, so a stable pill adds no timeline noise. Opening DevTools or resizing does not clear the buffer.

The Phase 1.7 fixture could not identify the historical live session's exact pre-DevTools geometry/style precursor: it modeled zero rectangles, inert timers/observers, and unconditional visible computed styles while asserting only `hidden === false`. The later Phase 1.8 integrity observer introduced a proven self-generated recovery loop by treating Chrome's canonicalized transform serialization as external damage. Phase 1.9 removes that observer, direct transform positioning, permanent retry timer, and pot-to-seat-discovery coupling instead of layering another recovery mechanism onto them.

Certified exact-manifest production-fixture measurements: an actual-live-shaped 1280×665 `.table-player.table-player-1.decision-current.you-player` fixture resolves card containers at `(658.2,452.5,74×86.1)` and `(708.2,452.5,74×86.1)` into the union `(658.2,452.5,124×86.1)` without a resize. The 100×60 vertical panel renders at `(548.2,465.55)` with an exact ten-pixel gap and aligned vertical centers. Replacing both card nodes discards three old observer references and immediately reacquires the new connected nodes. Narrowing reuses the same host and semantic fingerprint. Stable 30-second holds add zero placement attempts, DOM writes, frames, timers, mutation records, or timeline events. The independent 1720×900 and 1160×900 fixtures and six-frame/zero-timer delayed-geometry gate also remain green.

Phase 1.1 permits the authoritative named live pot for exactly two live contenders when the sole opponent is all-in, sets the highest live commitment, and the canonical user can fully match it. This configuration cannot create a side pot for which the user is ineligible. Short-stack partial-history calls, multiway all-ins, explicit ambiguity, and unresolved excess remain fail closed unless complete contributions or resolved side-pot evidence prove the eligible amount. Diagnostics now include bounded actor, price, stack, player-status, pot-source, eligibility-source, and rejection-gate evidence.

This phase does not inspect hole cards, enumerate outs, detect draws, estimate ranges/equity, make recommendations, calculate EV/implied odds, or persist pot odds to session/career records.
